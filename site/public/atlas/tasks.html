    Atlas: tasks/

    TLDR

    These are Windows Task Scheduler definitions for the future operational rhythms: a fallback heartbeat, the night cycle, and the weekly index. Every definition is tracked for review but ships disabled and unregistered. Exact schedules, task coordinates, machine paths, and hosting details are withheld. Static verification proves safe defaults; a human-run import-and-remove rehearsal proves host compatibility before arming.

    What this page covers

    Each XML file describes a trigger, wake behavior, execution command, and disabled settings. They are configuration schemas, not evidence that any job is running. The common safety pattern is more important than the hidden coordinate: an accidental import remains disabled, the host may wake for an enabled future job, and registration happens only after the hosting gate and the associated developmental phase close.

    File entries

    tasks/edgeweaver-heartbeat.xml schema-data

    What it is. The disabled definition for a fallback heartbeat wake when event-driven contact is unavailable.
    What it contains. It declares a repeating trigger, wake capability, a waking command, and disabled registration settings. Schedule and machine coordinates are not published.
    Who reads it and when. An operator imports it only after the body and hosting gates close; static verification reads it now.
    How to verify or reproduce it. Require well-formed XML, a trigger, wake enabled, task disabled, and the expected wake-command shape, then use the private import-and-remove rehearsal.
    Related concepts. See proactive attention, scheduling, and waking policy.

    tasks/edgeweaver-night-loop.xml schema-data

    What it is. The disabled definition for the recurring night-loop and coherence job.
    What it contains. It declares the calendar-shaped trigger, wake behavior, command sequence, working context, and disabled settings. Exact timing and host paths are withheld.
    Who reads it and when. An operator may register it only at the authorized phase and hosting gate; verifiers inspect it while dark.
    How to verify or reproduce it. Check XML structure, disabled state, wake capability, trigger class, and command shape, followed by the self-cleaning host rehearsal before arming.
    Related concepts. See night metabolism, coherence, and the orchestrator.

    tasks/edgeweaver-weekly-index.xml schema-data

    What it is. The disabled definition for the weekly rebuild, review digest, and boundary-registry maintenance job.
    What it contains. It declares a weekly trigger, wake behavior, chained command shape, and disabled settings, while this site withholds its operational coordinate.
    Who reads it and when. An operator registers it only after the same hosting and phase gates as the night task.
    How to verify or reproduce it. Statically require its trigger, disabled state, wake capability, and command shape; then privately prove disabled import and complete removal on the host.
    Related concepts. See weekly rebuilding, human review, and autobiography.
