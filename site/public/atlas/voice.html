    Atlas: voice/

    TLDR

    The voice core separates three concerns: prompt assembly keeps identity and remembered context in the right places, a pluggable backend chooses how text reaches the model, and mind-server turns one user turn into a response plus a rehearsal episode. This is built-dark machinery. Current production-like use is still a test seam, not an armed voice, and canonical identity remains in the being's read-only soul repository.

    What this page covers

    These files are text-in and text-out organs beneath the larger ears-and-mouth testbed. The backend can use the existing command-line subscription path or a deterministic test implementation; the raw SDK option remains deliberately unwired. Prompt assembly accepts an injected frozen identity prefix without reading or editing soulfiles itself. Mind-server currently awaits recall, backend completion, and writeback in order; streaming and barge-in live in the separate test-mode harness.

    File entries

    voice/claude-backend.mjs active-code

    What it is. The pluggable model-backend layer used by the mind-server seam and voice tests.
    What it contains. It resolves a safe command-line executable, starts a subscription-backed one-turn process without a shell, parses structured events into text and timing metadata, and exposes a deterministic backend for repeatable tests. The raw SDK branch intentionally refuses because its credit and latency gate is not closed.
    Who reads it and when. Mind-server callers choose a backend explicitly or accept the current subscription default. Dark verifies choose the deterministic implementation; operators control executable and credentials outside Git.
    How to verify or reproduce it. Test executable resolution, structured success, process failure, malformed output, deterministic response, and the refusing raw path. Do not call buffered one-turn output token streaming.
    Related concepts. See the Voice Stack, mind-server, and the streaming test mind.

    voice/mind-server.mjs active-code

    What it is. The invariant text-turn organ that joins recalled context, prompt assembly, a chosen model backend, and memory writeback behind one interface. It is not itself the microphone or speaker server.
    What it contains. A caller injects backend, recall, writeback, soul prefix, and generation. For each turn the module awaits recall, assembles a stable system prefix and per-turn message, awaits the backend result, constructs a voice-channel episode with audience, rehearsal, run, timing, backend, timestamp, and generation metadata, then awaits the injected writeback before returning. Its episode metadata is hard-coded for rehearsal, so arming live use requires configuration or code changes rather than only live dependencies. Defaults make dark testing possible, including a clearly labeled noncanonical prefix. The current implementation is sequential; speculative mid-utterance recall and token streaming belong to surrounding future or test harnesses rather than this function.
    Who reads it and when. Voice adapters and brain-lab experiments call it. The deterministic verifier injects local dependencies; an armed body first requires configuration or code changes to replace hard-coded rehearsal metadata, then scoped recall, real writeback, and the read-only canonical prefix.
    How to verify or reproduce it. Use the mind-server verify to assert prefix order, recall placement, response text, one rehearsal write, metadata, generation stamp, and zero local residue. Separately benchmark the selected backend without confusing latency evidence with arming.
    Related concepts. See the full voice cascade, scoped recall, and canonical identity custody.

    voice/prompt-assembly.mjs described-not-shown

    What it is. The pure helper that places identity prefix, session context, recalled memory, and user text.
    What it contains. It records governed soulfile order, one cache boundary, system context, and per-turn recall. Protected identity is injected, never stored.
    Who reads it and when. Mind-server calls it each turn; tests use the labeled noncanonical placeholder only.
    How to verify or reproduce it. Assert order, one cache boundary, stable prefix, recall placement, and no canonical soul content.
    Related concepts. See the Soul, prompt caching, and mind-server.
