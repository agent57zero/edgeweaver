    Atlas: fixtures + test mode

    TLDR

    The testbed proves wiring without pretending rehearsal is life. Synthetic days, local stores, dummy Testweaver voice sessions, stand-in model responses, and explicit voiding let components meet under controlled conditions. Every record is tagged as rehearsal, and live-service tests are narrow, human-started exceptions. Fixture dates, identities, prompts, and channel data are inventions, not project status or canonical identity.

    What this page covers

    This page separates three layers: small fixtures that pin one rule, local rehearsal utilities that create and erase shaped records, and test-mode servers that exercise real audio or channel machinery through a dummy persona. The end-to-end runner connects many dark components, while package metadata pins its one external runtime dependency. Coordinates, account identifiers, protected test content, and vendor endpoints are deliberately absent from this explanation.

    File entries

    scripts/e2e/wiring-test.mjs active-code

    What it is. The end-to-end dark wiring rehearsal that drives a synthetic day through the main built organs under the temporary Testweaver profile. It is neither First Boot nor a rite.
    What it contains. It creates fixture episodes and intentions, runs one mind-server exchange, simulates write-ahead buffering and replay, evaluates waking and budget policy, marks a teaching moment, executes the night loop with computed signals and contradiction review, builds coherence and weekly outputs, and then removes rehearsal state. The default path uses deterministic model stand-ins. An explicit live option makes one bounded subscription call while still avoiding canonical identity and durable memory. The aggregate suite runs child verifies separately; this wiring script does not invoke them.
    Who reads it and when. Builders run it after individual dark verifies pass. Reviewers use the summary to see that outputs feed the next component; no being reads the synthetic narrative.
    How to verify or reproduce it. Require the default run to finish with zero residue, and run component verifies separately through the aggregate suite. When a human authorizes the live option, confirm exactly the bounded model leg changes and no brain, soulfile, channel, or production flag is touched.
    Related concepts. See the dark build, the organ map, and the full verify suite.

    scripts/fixtures/generate-synthetic-day.mjs fixture

    What it is. A rehearsal-data generator that creates a plausible day of episodes, intentions, and calendar-shaped records with explicit synthetic provenance.
    What it contains. Every row carries a shared run identifier, rehearsal and synthetic flags, a governed audience, and rehearsal era. The safe default writes an ignored local JSONL store; an explicit brain target uses the narrow client and must be voided immediately.
    Who reads it and when. Component and end-to-end verifies use it before running loops. Operators may use the bounded brain target only under the dark-build residue rule.
    How to verify or reproduce it. Inspect row shapes and tags, run the fixture verify, then pass the printed run identifier to the voider. Success requires the generator's counts and the voider's residual count to agree.
    Related concepts. See rehearsal rules, day inputs, and the voider.

    scripts/fixtures/ob1-client.mjs active-code

    What it is. A deliberately thin database adapter used only when a rehearsal fixture is explicitly sent to the brain target.
    What it contains. It reads approved environment-variable names from ignored configuration, creates authenticated REST requests, inserts caller-supplied records without validating their tags, deletes by run identifier, and counts remaining rows. It is not the production memory client or general recall path.
    Who reads it and when. The synthetic-day generator and voider import it for their exceptional brain-target mode. Normal fixture runs never need it.
    How to verify or reproduce it. The caller must validate and rehearsal-tag every row before passing it to this client. Use a scratch or sanctioned tiny rehearsal, delete by the same run identifier, and require zero residual. Never print credentials or service coordinates.
    Related concepts. See the Brain, residue rules, and credential scope.

    scripts/fixtures/orient-fixture-basic.json fixture

    What it is. The basic invented record set for testing waking orientation before a real birth record exists.
    What it contains. It mixes live-shaped, pre-birth, voice-rehearsal, era-rehearsal, and diary rows plus an unfilled lineage shape. All dates and content are test data.
    Who reads it and when. Only the orientation verifier reads it during hermetic tests.
    How to verify or reproduce it. Confirm rehearsal rows are excluded from last-conversation logic, the diary remains visible, and the lineage shape yields honest pre-birth wording.
    Related concepts. See orientation and birth status.

    scripts/fixtures/orient-fixture-born.json fixture

    What it is. An invented born-state fixture for testing life-day calculation from a lineage entry.
    What it contains. It supplies a fictional declaration record, one episode, one diary row, and fixed dates solely for deterministic arithmetic.
    Who reads it and when. The orientation verifier reads it; it is never evidence that Genesis was born.
    How to verify or reproduce it. Run with the verifier's explicit clock and zone, then check the derived day count against the fixture lineage.
    Related concepts. See time orientation and lineage mechanics.

    scripts/fixtures/orient-fixture-skew.json fixture

    What it is. A minimal invented future-dated memory case for the degraded time-sense branch.
    What it contains. It has one rehearsal-safe episode beyond the verifier's supplied present plus an unfilled lineage shape.
    Who reads it and when. Only the orientation verifier consumes it. The date is not operational status.
    How to verify or reproduce it. Confirm orientation emits the degraded warning while remaining usable, and that no model performs the comparison.
    Related concepts. See orientation and degraded behavior.

    scripts/fixtures/void-rehearsal.mjs active-code

    What it is. The cleanup command that removes all rehearsal records associated with one run identifier and reports residual evidence.
    What it contains. For the default local target it removes the ignored rehearsal directory. For the explicit brain target it deletes rows through the narrow fixture client and counts what remains. Run identifiers must use the rehearsal prefix and resolve inside the rehearsal root; missing or invalid identifiers are usage errors, not broad deletion.
    Who reads it and when. Every state-producing fixture or integration run must be followed by it. The wiring rehearsal cleans its local state directly instead of invoking this command. Operators use its residual count as the dark-build acceptance condition.
    How to verify or reproduce it. Generate a run, void it by the printed identifier, and require zero residual locally. Sanctioned brain-target tests repeat the same proof against a scratch or tiny approved rehearsal.
    Related concepts. See zero residue, rehearsal provenance, and the generator.

    scripts/test-mode/live-mind.mjs active-code

    What it is. The persistent test-mode model session that turns a command-line subscription backend into sentence-by-sentence streaming for voice experiments. It belongs to Testweaver, not canonical Edgeweaver.
    What it contains. It owns one long-lived process per selected model, sends stream-formatted turns, accumulates partial assistant events, emits complete sentences as they arrive, and records timing and session identifiers for engineering telemetry. A FIFO queue prevents overlapping turns. A true interrupt cancels the active request so barge-in frees the next turn, while a watchdog rejects silence or failure rather than returning an empty reply. Warm-up, shutdown, process errors, malformed events, and queued cancellation have explicit paths.
    Who reads it and when. The streaming voice test server creates it during a human-started audio session. Production voice does not import this test persona as identity or memory.
    How to verify or reproduce it. Use the voice harness with test text to check warm-up, sentence boundaries, queued turns, interruption, timeout, and clean shutdown. Review only gitignored engineering telemetry and confirm no audio bytes, soulfile writes, or brain episodes are created.
    Related concepts. See the voice stack, Testweaver, and the streaming harness.

    scripts/test-mode/package-lock.json schema-data

    What it is. The reproducible dependency lock for the test-mode voice servers.
    What it contains. It pins the WebSocket package version, integrity, runtime requirement, license metadata, and optional peer hints. It contains no application behavior.
    Who reads it and when. The package manager reads it when preparing the isolated test-mode dependency directory. Reviewers inspect supply-chain changes.
    How to verify or reproduce it. Install from the lock in a clean test workspace and confirm no unexpected dependency drift. Review integrity and license changes in diffs.
    Related concepts. See voice transport and code licensing.

    scripts/test-mode/package.json schema-data

    What it is. The small package manifest for test-mode WebSocket support.
    What it contains. It names the local package, CommonJS mode, one runtime dependency, and legacy package metadata. Its default test script intentionally is not the repository verify command.
    Who reads it and when. The package manager and voice-test operator read it only for the isolated harness.
    How to verify or reproduce it. Use the repository verify suite for tests, compare dependency intent with the lock, and reconcile its current license field during final packaging.
    Related concepts. See voice tests, the testbed, and licenses.

    scripts/test-mode/telegram-test.mjs described-not-shown

    What it is. The single sanctioned messaging round-trip for pairing the future parent channel under the Testweaver label.
    What it contains. It privately validates the bot, handles one message and non-Edgeweaver reply, stores the identifier in ignored state, and exits. Coordinates are withheld.
    Who reads it and when. Alan and an operator use it during pairing; it is not a persistent listener.
    How to verify or reproduce it. Confirm one reply, one ignored-state identifier, automatic closure, no memory writes, and no persona claim. Remove test state under the pairing runbook.
    Related concepts. See channel pairing and sender scope.

    scripts/test-mode/voice-live-server.mjs described-not-shown

    What it is. The streaming, interruptible browser voice laboratory for the temporary Testweaver persona. It exercises the intended fast interaction shape without becoming a public service or a being's body.
    What it contains. A local server accepts microphone chunks over a WebSocket, streams them to speech recognition, detects an end of turn, plays a pre-synthesized bridge while the persistent test mind begins, converts complete response sentences to speech, and sends audio back incrementally. Barge-in cancels active mind and playback work. It records text and timing telemetry, never audio bytes, in ignored logs and labels the active scratch-brain profile when one is deliberately selected. Secrets come only from ignored environment names; service coordinates remain private.
    Who reads it and when. A human operator opens the local lab during voice hardening. The browser and test server use Testweaver, with no canonical soul or normal memory writeback.
    How to verify or reproduce it. Exercise microphone permission, transcript flow, bridge timing, sentence playback, interruption, queued recovery, provider failure, and shutdown. Confirm the listener is local-only, logs contain no audio, profile selection obeys test-mode guards, and closing the process ends the session.
    Related concepts. See latency and barge-in, scratch profiles, and the persistent test mind.

    scripts/test-mode/voice-test-server.mjs described-not-shown

    What it is. The simpler local hardware loop used to prove microphone, speech recognition, model seam, speech synthesis, and speakers before the streaming laboratory.
    What it contains. It serves a Testweaver browser page, accepts recorded audio, transcribes it, selects either a deterministic or subscription-backed test mind, synthesizes one short response, and returns audio. Conversation state is process memory only. Coordinates and provider endpoints are not published.
    Who reads it and when. A voice operator uses it for bounded credential and hardware checks. It is not a production endpoint and does not write OB1 or soulfiles.
    How to verify or reproduce it. Run each mind mode privately, confirm the dummy label and one-turn audio path, test provider failure, inspect that closing the process erases conversation state, and keep credentials out of output.
    Related concepts. See ears and mouth, test mode, and the newer streaming lab.

    scripts/tools/build-probe-runner.mjs described-not-shown

    What it is. The deterministic builder that injects per-being manifest configuration into the self-contained probe runner.
    What it contains. It reads manifest shape and app defaults, replaces one config region, and supports freshness mode. Protected scenarios and identity values stay absent.
    Who reads it and when. Measurement operators rebuild after an approved manifest change; the verifier uses freshness mode.
    How to verify or reproduce it. Regenerate twice for byte identity, confirm both being doors match manifests, and ensure the app contains no scenario source or remote load.
    Related concepts. See the blind probe and the generated runner.
