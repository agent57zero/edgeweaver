    Atlas: tools/

    TLDR

    The tools folder contains the self-contained human interface for blinded identity-probe runs. It opens from disk, keeps one being on screen, accepts answers without ever receiving scenario text, supports separated gut and formal rating passes, and prepares governed export files for a human to transfer to the private gates repository. Browser storage is scratch, not the canonical record. Protected scenarios, thresholds, answers, and identity values are not reproduced here.

    What this page covers

    This page explains the runner's safety shape rather than its protected battery. Configuration is deterministically injected from public manifest fields by the tracked builder. The interface guides a human through one session at a time, preserves the no-comparison wall between beings, and offers explicit export and purge actions. Static verification checks freshness, self-containment, equal governed battery shape, routing, and the absence of scenario source.

    File entries

    tools/probe-runner-targets.json described-not-shown

    What it is. Registry of targets the shared probe runner can open.
    What it contains. It maps each target to a manifest and carries runner-only presentation, model-note, status, battery-label, rater, generation, and governed evaluation defaults. It contains no scenarios, answers, scores, or credentials.
    Who reads it and when. The builder reads it when generating target doors; maintainers edit it when adding a governed target.
    How to verify or reproduce it. Run the probe-runner builder and verifier, then confirm both family targets remain manifest-backed and isolated.
    Related concepts. See blind measurement and the builder.

    tools/probe-runner.html described-not-shown

    What it is. Browser app for Alan's blinded probe workflow.
    What it contains. It manages setup, answers, ratings, results, export preparation, import, and scratch purge. It prepares export files for human transfer to the governed gates repository; it never transfers them. Scenarios and protected values stay absent.
    Who reads it and when. Alan uses it in a governed probe and transfers files; reviewers receive authorized exports.
    How to verify or reproduce it. Check freshness and static walls; open from disk without remote loads. Never use scenarios publicly.
    Related concepts. See blind measurement, gates wall, and its builder.

    tools/probe-runner.md runbook

    What it is. Operating guide for repository-backed probe records.
    What it contains. It defines the private gates-repository folder layout, resumable run record, save and fallback-download paths, target-onboarding procedure, generation and version labels, and security boundary. It keeps protected evaluation material out of this repository.
    Who reads it and when. Alan and authorized build agents use it before saving, resuming, transferring, or extending a probe run.
    How to verify or reproduce it. Follow its builder and verifier commands; confirm the runner never receives scenario text or network credentials.
    Related concepts. See governance, measurement, and the verifier.
