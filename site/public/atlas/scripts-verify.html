    Atlas: the verify suite

    TLDR

    The verify suite is the repository's fixed rope: each component ships a repeatable check that prints a first-line result and exits nonzero on failure. Most checks are hermetic dark rehearsals using fixtures, temporary directories, or injected dependencies. They prove named invariants, not every live service. The aggregate runner discovers JavaScript verifies automatically; live machine checks remain explicit and out of band.

    What this page covers

    Entries name what each check pins, the boundary of its evidence, and how it avoids unauthorized side effects. Short component verifies point back to the code they exercise. Larger checks cover cross-file invariants: fleet isolation, dump safety, memory scoping, restore metadata, site release rules, and complete night wiring. A green result is useful only for the exact contract the check actually runs.

    File entries

    scripts/verify/run-all.mjs active-code

    What it is. The aggregate dark-verify runner and standard repository health command.
    What it contains. It discovers every JavaScript file whose name begins with the verify prefix, runs them in sorted order with the current Node executable, captures each first output line, and prints a compact pass/fail table plus an all-pass summary. It does not discover the PowerShell live task-import check.
    Who reads it and when. Builders and operators run it after a coherent change set and inside the repository recovery drill. Individual component output remains available when a row fails.
    How to verify or reproduce it. Add a temporary failing fixture in an isolated copy to prove nonzero propagation, then remove it. Keep every child verify's first line stable and actionable.
    Related concepts. See the dark build, verification cadence, and site verification.

    scripts/verify/task-import-test.ps1 described-not-shown

    What it is. The out-of-band Windows task import-and-remove rehearsal used only at arming.
    What it contains. It converts tracked task definitions to the encoding required by the scheduler, registers each under a temporary test name, confirms disabled state, then removes it. Coordinates are withheld.
    Who reads it and when. An operator runs it on the intended host; the aggregate JavaScript suite does not.
    How to verify or reproduce it. Require every temporary task to register disabled and require cleanup even after failure. Inspect the host privately for residue.
    Related concepts. See scheduled operations and task definitions.

    scripts/verify/verify-ab-run.mjs active-code

    What it is. The hermetic command-contract check for the brain A/B runner.
    What it contains. It uses a tiny invented question file and dry-run child processes to pin candidate validation, usage errors, and the no-resolution dry path.
    Who reads it and when. The aggregate suite runs it before any lab experiment.
    How to verify or reproduce it. A named live profile must remain harmless in dry-run, while missing or malformed candidate input must fail with usage status.
    Related concepts. See A/B testing and the runner.

    scripts/verify/verify-brains.mjs active-code

    What it is. The primary hermetic verify for brain registry shape, selection guards, generation stamps, pure SQL planning, and live-copy dry-run.
    What it contains. It tests profile resolution with saved environment state, refusal of live in test mode, schema-version mismatch, generation metadata, scratch naming, DDL rewrite, extension treatment, policy retention, dependency copy order, count queries, and a child spawn plan in a temporary root. No database is contacted.
    Who reads it and when. The aggregate suite runs it whenever fleet code or schema conventions change. Lab operators use it before a real scratch operation.
    How to verify or reproduce it. Keep its synthetic DDL representative of every construct used by canonical brain DDL. A new migration feature needs a pinned case before live propagation.
    Related concepts. See brain fleets, profile guards, and SQL generation.

    scripts/verify/verify-budget.mjs active-code

    What it is. The pure boundary test for resource warning, degradation, voice accumulation, and unset-ceiling behavior.
    What it contains. It applies invented spend values to the budget helpers and checks that optional work is suppressed only at the governed cap.
    Who reads it and when. The aggregate suite runs it; no real cost or policy value is read.
    How to verify or reproduce it. Keep cases below warning, at warning, at cap, and unset, plus voice-minute accumulation.
    Related concepts. See resource policy and the meter.

    scripts/verify/verify-coherence.mjs active-code

    What it is. The fixture check for coherence computation and static panel rendering.
    What it contains. It supplies invented thoughts and edges, expects honest cold-start nulls, computes available measures, and parses the rendered page for labels and values.
    Who reads it and when. The aggregate suite runs it before panel changes.
    How to verify or reproduce it. Maintain cases with recent evidence, open tension, missing history, and recovery state; never replace null with a guessed score.
    Related concepts. See coherence and the calculator.

    scripts/verify/verify-dr.mjs active-code

    What it is. The repository-machinery recovery check and recursion guard.
    What it contains. It validates required runbook concepts, then invokes the clone-and-verify drill unless already inside that drill, where it avoids infinite nesting.
    Who reads it and when. The aggregate suite and recovery operator use it.
    How to verify or reproduce it. Require the local clone to reach all-pass and report recovery time, while recognizing that secrets, soul, and brain restore are separate evidence.
    Related concepts. See disaster recovery and the drill.

    scripts/verify/verify-dump-spawn.mjs active-code

    What it is. The load-bearing data-integrity verify for opening a past brain from a full database dump.
    What it contains. It builds a synthetic dump with structural statements, related tables, extension metadata, functions, copy blocks, and data deliberately resembling rewrite targets. It segments both sides and demands byte-identical data while checking the permitted DDL changes. It also runs past-spawn dry-run and the ordinary brain verify as child processes.
    Who reads it and when. The aggregate suite runs it before any dump-transform, SQL-policy, or past-spawn change.
    How to verify or reproduce it. Preserve the trap data row and physical-boundary cases. A passing dry plan is not a real restore; the lab rehearsal and human-held decryption remain separate.
    Related concepts. See past brains, dump transformation, and backup custody.

    scripts/verify/verify-evidence-cluster.mjs active-code

    What it is. The synthetic threshold and confirmation check for evolution evidence clustering.
    What it contains. It creates used and ignored traces plus confirmed, unconfirmed, well-cited, and under-cited memories, then checks only eligible evidence clusters.
    Who reads it and when. The aggregate suite runs it before evolution changes.
    How to verify or reproduce it. Keep all exclusion cases and assert returned identifiers and citation counts, not identity conclusions.
    Related concepts. See earned change and the clusterer.

    scripts/verify/verify-feelings.mjs described-not-shown

    What it is. The local fixture check for boundary and commitment registries plus all four directional signal functions.
    What it contains. It uses invented source material and histories to cover provenance, gate-decline exclusion, overdue state, novelty cold start, and experiment or loop outcomes. Protected text is absent.
    Who reads it and when. The aggregate suite runs it with temporary ignored state.
    How to verify or reproduce it. Require generated shapes, bounded results, novelty ordering, and cleanup. Do not treat fixture language as identity or feeling.
    Related concepts. See computed signals and the calculator.

    scripts/verify/verify-fixtures.mjs active-code

    What it is. The zero-residue proof for the default local synthetic-day workflow.
    What it contains. It generates one invented day, checks plausible record classes and rehearsal tags, voids by run identifier, and asserts the local store is gone.
    Who reads it and when. The aggregate suite runs it without a brain connection.
    How to verify or reproduce it. Any new fixture type must retain synthetic, rehearsal, audience, era, and shared-run metadata and must disappear on void.
    Related concepts. See rehearsal safety and the generator.

    scripts/verify/verify-flags.mjs active-code

    What it is. The dark-by-default check for generated operational flags.
    What it contains. It rebuilds ignored flag state, parses it, and requires every known component, task, and channel to exist disabled and unregistered.
    Who reads it and when. The aggregate suite runs it after default-schema changes.
    How to verify or reproduce it. Confirm initialization preserves existing values in its own tests while this check proves the committed default never arms machinery.
    Related concepts. See dark defaults and the initializer.

    scripts/verify/verify-import-filter.mjs active-code

    What it is. The hermetic selector test for the Phase 0a conversation import filter.
    What it contains. Invented conversations exercise identifier matching, title matching, unrelated dropping, and the reported kept and dropped totals.
    Who reads it and when. The aggregate suite runs it; real export content and selectors never enter the fixture.
    How to verify or reproduce it. Keep both positive routes and unrelated negatives, and require the counts to reconcile with the input total.
    Related concepts. See Phase 0a and the filter.

    scripts/verify/verify-initiation.mjs described-not-shown

    What it is. The throwaway-repository rehearsal for the identity proposal workflow.
    What it contains. It drafts a governed proposal artifact, attaches invented score evidence, checks the cooling-off marker, and deletes the sandbox. Protected identity and probe material are omitted.
    Who reads it and when. The aggregate suite runs it; no canonical soul repository is targeted.
    How to verify or reproduce it. Require cited evidence shape, proposal-only behavior, cooling-off metadata, and zero sandbox residue. It must never merge.
    Related concepts. See initiation, canonical identity, and the proposer.

    scripts/verify/verify-mind-server.mjs active-code

    What it is. The repeatable dark verify for prompt assembly, recalled context, backend output, episode writeback, and cleanup at the mind-server seam.
    What it contains. Its default uses a deterministic backend, injected recall, and a local rehearsal store. It pins frozen-prefix order and cache breakpoint, confirms recalled context reaches the turn, checks voice episode metadata, and removes the store. An explicit benchmark mode permits one bounded subscription call and records latency without changing the default suite.
    Who reads it and when. The aggregate suite runs the deterministic path. Voice engineers opt into the benchmark only when measuring the later conversational gate.
    How to verify or reproduce it. Require no network in default mode, exact rehearsal and generation tags, one writeback, complete cleanup, and a clearly separate benchmark result.
    Related concepts. See the mind seam, mind-server, and prompt assembly.

    scripts/verify/verify-night-loop.mjs active-code

    What it is. The end-to-end local contract check for one rehearsal night and its idempotent rerun.
    What it contains. It creates a synthetic day, executes the night orchestrator with deterministic dependencies, and checks evidence citations, four-number interpretation shape, completion, one bounded fiction record, concrete expectations and intention, importance adjustment, contradiction review, and panel metrics. It reruns the same identifier to require skips and no duplicate dream, exercises missed-run alert logic, and removes rehearsal state.
    Who reads it and when. The aggregate suite runs it before lifecycle changes; operators use its failure list to locate the broken step.
    How to verify or reproduce it. Keep every contract assertion tied to the night-loop specification and require zero residue even after a failing branch. It proves dark wiring, not live scheduling.
    Related concepts. See nightly metabolism, the orchestrator, and signals.

    scripts/verify/verify-ops-log.mjs active-code

    What it contains. It requires the file, cadence definitions, a log section, at least one dated entry, and a reference to scheduled task definitions.
    Who reads it and when. The aggregate suite runs it; human review still judges whether entries are truthful.
    How to verify or reproduce it. Add ledger changes in the documented table shape and confirm the checker detects missing sections or an empty log.
    Related concepts. See the ledger and task evidence.

    scripts/verify/verify-orient.mjs described-not-shown

    What it is. The hermetic temporal and being-scope check for waking orientation.
    What it contains. It drives invented alive, pre-birth, rehearsal, lineage, skew, and diary-window fixtures through explicit clock and zone inputs. Operational times are omitted here.
    Who reads it and when. The aggregate suite runs it with no network, environment file, or soul repository.
    How to verify or reproduce it. Require rehearsal exclusion, honest pre-birth phrasing, fixture life-day math, degraded skew, and correct governed window boundaries.
    Related concepts. See orientation and the command.

    scripts/verify/verify-probe-runner.mjs described-not-shown

    What it is. The static wall check for the self-contained probe application and its generated configuration.
    What it contains. It checks builder freshness, manifest-aligned doors, equal governed scoring shape, no scenario text, no comparison view, no remote loads, and correct routing. Sensitive thresholds stay omitted.
    Who reads it and when. The aggregate suite runs it; private gates remain outside the application and this site.
    How to verify or reproduce it. Change manifests or builder inputs, rebuild once under ownership, then require deterministic freshness and every wall before use.
    Related concepts. See blind probes and the runner.

    scripts/verify/verify-recall-scoping.mjs active-code

    What it is. The offline, fixture-pinned proof for fail-closed audience and provenance filtering at the recall wrapper.
    What it contains. It has three legs: source inspection pins the unlabeled default, a logic replica exercises scope and class combinations including the governed pre-birth default, and a mirror check requires the reviewed source and deployable recall function to be byte-identical. It uses no credentials or network.
    Who reads it and when. The aggregate suite runs it after memory-convention or recall-function changes. Runtime consumers depend on this wall even though they do not run the verify.
    How to verify or reproduce it. Keep fixture rows for unlabeled, experienced, interpretation, fiction, library, and every audience scope. A source change must update the replica deliberately and preserve mirror equality.
    Related concepts. See recall walls, the deployable wrapper, and audience algebra.

    scripts/verify/verify-restore-point.mjs active-code

    What it is. The hermetic evidence check for gathering and maintaining the committed restore-point map.
    What it contains. Injected repository and release readers produce a record without real shell calls. Cases cover row-count wording present or absent, normalized dates, reference shortening, JSONL append then same-date replacement, invalid CLI usage, and a dry-run in a fresh root with external commands unavailable.
    Who reads it and when. The aggregate suite runs it before restore-map code changes. Operators later compare real references privately before committing a map line.
    How to verify or reproduce it. Preserve the blank-path test that proves dry-run cannot accidentally shell out, and require absent evidence to become null rather than a guess.
    Related concepts. See restore points, the map writer, and backup evidence.

    scripts/verify/verify-security-audit.mjs described-not-shown

    What it is. The aggregate-shape check for the five-part security audit.
    What it contains. It calls the audit, requires every named leg to report, and fails when any current-machine result fails. Sensitive targets and coordinates are not repeated here.
    Who reads it and when. The aggregate suite runs it where the relevant local checks are meaningful. Operators still perform arming-time host review.
    How to verify or reproduce it. Confirm all five results are independent and a forced failed leg propagates nonzero without printing secret values.
    Related concepts. See security review and the audit.

    scripts/verify/verify-site.mjs active-code

    What it is. The deterministic verification wall for this explainer, with separate default, live-drift, redaction, and release modes. It reports paths and labels, never protected values.
    What it contains. Default checks builder freshness, navigation metadata, generated local search, internal links and anchors, Atlas manifest consistency, style rules, external-resource policy, secret shapes and values, gate basics, HTML structure, probe overlap, and artifact self-containment. Live mode compares mapped anchors with tracked paths while distinguishing reportable new drift from true orphan or mapping failures. Redaction mode derives protected identity and people rules from authority sources, requires the ignored operational denylist, and scans pages, search, and artifacts. Release mode adds final metadata, zero placeholders, reading-register pairing, accessible table and diagram semantics, complete Atlas fields, allowed badges, and depth word bands.
    Who reads it and when. Luna runs targeted modes during integration; root requires the appropriate matrix at each freeze. The full repository runner includes default mode automatically.
    How to verify or reproduce it. Keep checks hermetic except the explicit tracked-file comparison. Add every generated content surface to secret and redaction scans, use fail-closed behavior when authority inputs are missing, and test the verifier with intentional stale, malformed, leaking, and incomplete fixtures before trusting a green release.
    Related concepts. See how the site is made, redaction, and the builder.

    scripts/verify/verify-study.mjs described-not-shown

    How to verify or reproduce it. Require only allowed library material to produce one experiment and retain its matrix identifier; no library row may become an episode.
    Related concepts. See study and the loop.
