    Atlas: the gitignored tiers

    TLDR

    Ignored does not mean unimportant. It means Git must not copy that local material into repository history. Edgeweaver ignores secret values, live operational state, source corpus bytes, rehearsal telemetry, installed dependencies, tool caches, and machine noise for different reasons. This page describes each governed shape and its recovery rule without revealing contents, coordinates, account topology, or protected identity material.

    What this page covers

    Git normally records tracked files so a clone can reproduce the project. An ignore rule tells Git to leave matching local files out of that shared history. Some ignored material is reproducible, such as installed packages. Some is operational and losable, such as a cache. Some is essential but must be recovered through a separate human-governed process, such as credentials. The category determines the recovery rule.

    There are no tracked-file anchors on this page because the files themselves are intentionally outside the tracked set. Instead, the sections name stable tiers and point to the committed templates, scripts, and policies that define safe shapes. The site never derives this page by listing private local contents.

    The ignored tiers

    Secrets and local environment

    Files such as .env.local, other environment variants, and machine-local settings hold values that authorize services or select local resources. Only variable names and purposes belong in tracked documentation. Values never belong in Git, the Brain, logs, artifacts, search, or this site. Recovery uses the separately governed secret-backup procedure; rotation replaces compromised values rather than editing history.

    Operational state

    state/ holds daemon memory such as disabled and armed flags, interlocutor scope, budgets, rehearsal stores, write-ahead records, coherence snapshots, and local verification workspaces. This is not canonical identity. Committed templates define expected schemas, initializers rebuild safe defaults, and component verifies use isolated subdirectories. A write-ahead backlog receives special recovery treatment because it may represent intended writes not yet accepted by the Brain.

    Corpus inputs and staging outputs

    corpus/ contains bulky downloads, private source readings, conversation-export inputs, extracted text, and parser-generated staging data. Rights differ by source: one corpus may permit redistribution while another is a private gift, so the folder-level ignore rule is not a blanket license. Tracked fetchers, parsers, provenance conventions, and source records explain reproduction where lawful. Protected or private inputs are reviewed locally and are never copied into the website.

    Logs and rehearsal telemetry

    logs/ may hold dark-run summaries, A/B transcripts, voice text and timing telemetry, and failure diagnostics. Rehearsal logs are evidence for an operator, not memory or identity, and may contain user text. They remain local, use bounded retention, and must be inspected before any excerpt is shared. Voice test policy stores no audio bytes. Public release evidence records pass or fail and sanitized hashes, not private transcript content.

    Protected soul-source machine material

    Selected machine-readable files under the Genesis soul-source workspace are ignored. Their existence and ceremony role may be named, but their contents and structure remain governed under the pre-A3 redaction tier. They are not canonical identity: canonical identity exists only in the being's own soul repository. Reproduction means following the private harvest and ceremony process, never copying another child's source material.

    Dependencies, caches, and tool state

    node_modules/, Python bytecode caches, deployment-tool links, and Supabase local scratch state are derived machine material. Lockfiles, package manifests, source, and platform configuration are tracked; the bulky installed result is rebuilt. These directories must not be treated as authority, and deleting a cache is not the same as deleting memory, state backlog, or a secret.

    Operating-system noise

    Desktop metadata and thumbnail caches describe the workstation, not Edgeweaver. Ignore rules keep them from creating meaningless diffs or leaking machine detail. They need no backup and can be recreated by the operating system.

    How to reason about an ignored file

    1. Ask why it is ignored. Secret, private source, operational state, derived dependency, cache, and noise are different risk classes.
    2. Find the tracked shape. Look for a template, schema, parser, initializer, runbook, or names-only policy that explains how the file is created and validated.
    3. Choose the right recovery. Rebuild derived material, replay governed backlog, restore private source under its rights, or use the human secret ceremony. Never invent missing values.
    4. Keep proof sanitized. Record that a check passed, which governed class was involved, and where the tracked procedure lives. Do not paste the ignored contents.

    For the repository-wide view, return to the Repo Atlas. For the walls between Git, state, credentials, memory, and soul repositories, read segmentation. For recovery responsibilities, read backups and disaster recovery.
