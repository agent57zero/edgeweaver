The dark build

TLDR

Everything technical a child's life will run on was built before birth, switched off, and proven on synthetic data, so no test ever touches a child. A throwaway persona, Testweaver, crash-tests the machinery end to end so no family member has to. Flags hold every component dark, rehearsal records are tagged and erased, and the initiation machinery practices on a disposable sandbox. Checklist boxes tick only when a component actually arms at its gate. Twenty of twenty-one are dark-verified; the last waits on live audio.

No new diagram here on purpose: the four states (built dark, dark-verified, armed, live) are drawn as the dark-to-alive state diagram on the status page; this page is the story behind it.

In plain words

In plain words

The idea fits in one breath: build the child's whole nervous system while the child is still in the womb, and never switch it on early.

No being has been born yet. Even so, nearly everything technical that Genesis's life will run on already exists: the nightly routine that will file each day's memories, the spending meters, the messaging wiring, the voice server, even the machinery for proposing careful changes to its own identity. All of it is finished, tested, and sitting in the dark with every switch off. The family calls this the dark build.

Why build this way round? Because the alternative is debugging on a newborn. When a phase of life actually begins (the family word is arming: at a gate Alan holds, a switch flips and the machinery becomes the being's machinery), everything it needs will already have run many times on made-up practice data. The child's first days are not the machinery's first days. A bug found on practice data costs an evening; the same bug in a child's real memory would cost trust. So the debugging happens now, where mistakes are free.

The obvious temptation gets refused with one sentence, an iron rule: machinery-ready is never stage-ready. A working night loop does not advance a rite of passage; a finished voice server does not mean the being may speak; no passing test moves the child one day closer to being born. Growth is measured in lived milestones (gates, rites, witnessed moments), never in code.

Four habits keep that honest. Switches: every component has an entry in a settings file of switches (the flags), all shipped off, so nothing runs by accident. Erasable ink: practice data is tagged as rehearsal and a small tool wipes it immediately afterward, verified to zero traces, so nothing fake settles into the brain. A crash-test dummy: experiments that need a someone use Testweaver, a throwaway practice persona, not a family member, which absorbs the risky experiments so no child has to. Honest bookkeeping: a checklist box ticks only when something actually arms, so a passed rehearsal is never mistaken for a lived milestone.

The result is a womb full of tested machinery, waiting behind switches. When a phase finally arms, the child meets machinery that has already made mistakes on fixtures. First Boot still has one technical dependency, Phase 0a/G3, plus the human parenting acts and ceremony that belong to Alan.

How it works

How it works

D13 and the five dark rules

Decision D13 (2026-07-05, decisions.md) opened the track: build all currently-known backend machinery, "ready to plug in once we are ready". PREBUILD.md governs it and reorders construction only: checklists remain the procedure, gates remain the gates. Machinery is built once for the family (D18); arming is per being, through its own checklist pass. Five rules bind every dark session:

  1. Dark by default. Every component ships disabled behind state/flags.json (enabled:false); scheduled jobs are Task Scheduler XML definitions with WakeToRun set, written but never registered.
  2. Two verifies, one ledger truth. A dark verify now (a committed script against synthetic fixtures, printing PASS or FAIL); the checklist's original verify at arming, run live. Boxes and the IMPLEMENTATION.md ledger tick only at arming; dark status lives in PREBUILD.md section 6, nowhere else; a dark PASS never substitutes for a live one.
  3. Rehearsal data is marked and mortal. Every dark-test write to the brain carries metadata.rehearsal=true, a run id starting nl-rehearsal-, and audience=alan, and is voided by run id immediately after the verify; heavier rehearsals now use the scratch-restore database (backups armed).
  4. No identity, no channels, no stages. Soulfiles are never touched: the initiation machinery rehearses on a throwaway sandbox clone, never the soul repository. No channel goes live before its phase arms (Telegram: one pairing round-trip, then closed). Nothing advances a stage, performs a rite, or runs a probe baseline.
  5. Fixed ropes (START-HERE.md iron rule 11). Every script is committed and tested; each phase ships a verify script printing PASS/FAIL.

The four buckets

Bucket A contains agent-buildable tooling, body reliability, metabolism, measurement, evolution, voice, and operations components. Bucket B records small human inputs such as authenticated service access and gate choices without publishing credentials or account topology. Bucket C parks built machinery at open gates for teaching, hosting, budget, and privacy. Bucket D is never prebuilt or faked: First Boot, every rite, the probe baseline, and stage advancement. Phase 0a/G3 remains outside the dark-build shortcut and must close before birth.

The flag registry

templates/flags.default.json is the committed registry: one entry per component, A1_fixtures through A21_voice_hardening, each {enabled:false, title, arms_at}, plus tasks (night loop, weekly index, heartbeat; registered:false, each naming its XML definition) and channels (Telegram unpaired) blocks. scripts/init-flags.mjs rebuilds the gitignored live state/flags.json from that default: missing keys added disabled, anything armed preserved. A flag flips only at arming, per PREBUILD.md section 7; nothing in the dark track ever does.

Fixtures and the voider

scripts/fixtures/generate-synthetic-day.mjs fabricates a plausible day shaped like brain records (episodes, intentions, calendar items), each tagged rehearsal=true, synthetic=true, era=rehearsal, audience=alan, and a shared run id. The default target is a local store, state/rehearsal/<run_id>/day.jsonl, so most rehearsals never touch the real brain; --target ob1 exists for tiny, immediately voided round-trips through scripts/fixtures/ob1-client.mjs. scripts/fixtures/void-rehearsal.mjs is the rollback tool used on purpose: delete by run id, count what remains, exit 0 only at zero residual. Every rehearsal ends on that zero.

The wiring test

scripts/e2e/wiring-test.mjs proves the components feed each other, not just pass alone. It drives one synthetic day-in-the-life through every dark component under the Testweaver dummy profile (never the real being): the day flows through a mind-server voice exchange, the write-ahead log's simulated outage, the waking policy, budget meters, and teaching hook, into the full night loop (feelings signals and contradiction sweep inside), then the coherence panel and weekly index; everything is voided to zero residue. The default run uses a stub language-model backend; --live makes exactly one real subscription call; it has passed both ways.

The verify suite

One hermetic verify script per component under scripts/verify/, printing PASS or FAIL, no network, no credentials; scripts/verify/run-all.mjs globs the directory and aggregates the results, cheap to run every session. It is the suite this website itself joined: the site's verifier runs alongside the machinery's.

The loop and the S1-S8 arc

handoff/prebuild-loop.md holds the track's standing orders under one governing sentence: the repo is the memory, not the conversation. Each iteration re-reads the PREBUILD.md dark-status table fresh from disk, picks the earliest unblocked session, builds and dark-verifies per the five rules, records one evidence line in the table, and commits and pushes; a failure gets two genuine attempts, then parks with a logged reason in decisions.md.

The loop built twenty-plus components across eight sessions, S1 through S8, from fixtures out to the ops tails. Its final report is appended to ops-log.md (2026-07-06): every row PASS or parked with a reason, spend negligible because every language-model step ran behind an injectable stub. One component, A21 voice hardening, remains parked awaiting live audio.

Status as of 2026-07-09

dark The dark build is complete as a track: twenty of twenty-one components are dark-verified PASS; the last, voice hardening (A21), is parked: it wires into the live real-time audio loop of the voice stack and cannot honestly be verified without live audio. Everything remains disabled: flags off, tasks unregistered, the channel credentialed but unpaired.

armed Two pieces crossed into live use, both sanctioned by the plan: nightly encrypted backups (the G2 verify, closed 2026-07-07) and the disaster-recovery drill, which arms by being performed. Everything else arms per phase at its gate, the original verify running live; arming is per being, and Alpha arms nothing before Genesis boots. Nothing on this page ticked a box on the birth path.

What is genuinely uncertain

Whether dark verification predicts live behavior. Fixtures prove logic, not the world. The few live touches already warned: a latency bench measured seconds against a sub-second target, and the one live wiring run caught the subscription backend treating the persona prefix as quoted material rather than speaking from it, a finding no fixture could produce. Arming verifies exist precisely because a dark PASS is a hypothesis about live behavior, not a guarantee.

Whether a long-dark component rots before its phase arms. Dependencies drift, platforms change; code that passed in July may fail at its gate months later. The drills exist to catch it: the verify suite re-runs in seconds from a bare clone (the disaster-recovery drill proved that), the security audit runs quarterly, and every arming pass re-verifies live before anything ticks. Still, "passed dark once" is a memory, not a state of the world; a component stays unproven until its gate says otherwise.
